# PGN の書き出しを独立した crate にしない

## Context and Problem Statement

Rust には PGN を読む実装はあるが、書き出す実装が見当たらない。
この空白を埋める汎用の crate を作るか、この repo の内部モジュールに留めるかを決める。

## Decision Drivers

* 実装量を必要な範囲に留めたい。
* 公開したものに対する保守の義務を、必要が生じる前に負いたくない。

## Considered Options

* 内部モジュールとして、必要な範囲だけ実装する。
* 汎用の crate として設計し、公開する。

## Decision Outcome

内部モジュールとして、必要な範囲だけ実装する。

書き出しに必要なのは、ヘッダと主手順と手ごとの注釈を並べる整形処理だけになる。
汎用の crate にすると、変化手順の入れ子、注釈記号の網羅、書き出し形式の行折り返し、ヘッダの順序といった仕様全体を引き受けることになり、自分では使わない部分が実装の大半を占める。

読み取り専用の実装しか存在しないのは、需要が小さいことの現れだと解釈する。
書き出しはアルゴリズムではなく整形処理であり、必要な人がその場で書いて済ませている。

### Confirmation

書き出しモジュールが、主手順と注釈以外の PGN 構文を扱っていないことを確認する。

## Consequences

### Good

* 実装量が整形処理の範囲に収まる。
* 仕様全体への追従義務を負わない。

### Bad

* 他の場所から再利用できない。
  変化手順を扱う必要が生じた時点でモジュールとして切り出す余地は残しておく。
* 書き出し形式の仕様に準拠しないため、厳密な読み手では扱えない可能性がある。
  参照実装が 6000 文字を超える 1 行を出力し、主要なツールがそれを読めていることを根拠に、実務上の問題は生じないと判断する。
