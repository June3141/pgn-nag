# 保持する状態を設定だけに限る

## Context and Problem Statement

`nag` を引数なしで起動して棋譜を選べるようにすると、棋譜の置き場所を知る必要が生じる。
engine の実行パスと悪手の閾値も、既に設定から解決すると決まっている。

一方で、閲覧した棋譜の一覧、最後に見た局面、解析結果の写しといった値も、保持すれば利便性が上がる。
どこまでを PGN の外に持つかを決める。

## Decision Drivers

* 引数なしの起動で棋譜を選べるようにしたい。
* 保持した値と実際のファイルが食い違う状態を作りたくない。
* 注釈付き PGN 1 ファイルで完結するという性質を壊したくない。

## Considered Options

* 設定だけを持ち、それ以外の状態は持たない。
* 設定に加えて、閲覧履歴や最後に見た局面を持つ。
* 設定に加えて、解析結果の写しを cache として持つ。

## Decision Outcome

設定だけを持ち、それ以外の状態は持たない。

設定は TOML で書き、置き場所は各 OS の慣行に従って解決する。
repo が既に TOML を使っているため、読み手が形式を覚え直さずに済む。

設定が持つのは、engine の実行パス、悪手の閾値、棋譜を置くディレクトリの 3 つになる。
前の 2 つは ADR-0007 と ADR-0006 の帰結として既に決まっており、この ADR で新たに増えるのは 3 つ目だけになる。

引数なしの起動は、設定された棋譜のディレクトリを読んで一覧を出す。
ディレクトリの中身がそのまま一覧になるため、別に索引を保持する必要が無い。
`nag view <file>` と `nag view <dir>` は引き続き設定に依らず動く。

解析結果の写しは持たない。
ADR-0006 が導出値を保存しないと決めており、cache はその決定を置き場所を変えて破ることになる。
評価値から分類までの計算は棋譜 1 局の手数では無視できる。

閲覧履歴と最後に見た局面も、今は持たない。
ファイルの移動・削除・再解析のたびに、保持した値と実体の食い違いをどう扱うかを決める必要が生じる。
無効化の設計に見合う利便性が得られるかは、実際に使ってからでないと判断できない。

### Confirmation

設定ファイルを削除しても、`nag view <file>` が動くことを確認する。
書き込む先が設定ファイルだけであり、他のディレクトリへ書かないことを確認する。

## Consequences

### Good

* 保持する値が設定 1 つに限られ、実体との食い違いが起きる箇所が増えない。
* 棋譜の一覧がディレクトリの内容そのものになり、無効化を考えずに済む。
* 設定を消しても、パスを指定する経路は動き続ける。

### Bad

* 棋譜を複数のディレクトリに分けている場合、一覧に出るのは設定した 1 つだけになる。
  パスを指定する経路が残るため、閲覧そのものは阻害しない。
* 前回見ていた局面が引き継がれない。
  必要になった時点で、無効化の方針と併せて判断する。
