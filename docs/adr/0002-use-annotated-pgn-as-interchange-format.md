# 中間形式に注釈付き PGN を使う

## Context and Problem Statement

解析工程と閲覧工程をファイルで繋ぐと決めた。
そのファイルの形式を選ぶ必要がある。

## Decision Drivers

* 自作の viewer 以外でも読めるようにしたい。
* 棋譜と解析結果が別々に散らばらないようにしたい。
* 既存の実装で読み書きを検証できるようにしたい。

## Considered Options

* 評価値を注釈として埋め込んだ PGN。
* 棋譜は PGN のまま、評価値を別ファイルの JSON に置く。
* 独自のバイナリ形式。

## Decision Outcome

評価値を注釈として埋め込んだ PGN を使う。

`{ [%eval 0.34,18] }` という書式は Lichess が用いている事実上の標準で、既存のツールと Python の実装が読み書きに対応している。

最善手順には標準のタグが存在しないため、同じ注釈の中に `[%pv ...]` を併記する。
PGN の読み手は未知の `%tag` を無視するため、他のツールを壊さない。

別ファイルの JSON は、棋譜とのひも付けを自前で管理することになり、片方だけが移動または削除された場合に破綻するため採らない。

### Confirmation

生成したファイルが Lichess の取り込み機能と既存の Python 実装の双方で読めることを確認する。
読み込みと書き出しの往復で内容が一致することを、テストデータで確認する。

## Consequences

### Good

* 棋譜と解析結果が 1 つのファイルに収まり、対応関係が壊れない。
* 自作の viewer が完成する前から、既存のツールで解析結果を閲覧できる。
* 既存の実装を参照して、書式の解釈を検証できる。

### Bad

* PGN の表現力に縛られ、標準タグの無い情報は独自タグに頼ることになる。
  未知のタグが無視される仕様に依存するため、他ツールでの表示は保証されないと割り切る。
* 最善手順を長く保存するとファイルが膨らむ。
  保存する手数に上限を設けて対処する。
