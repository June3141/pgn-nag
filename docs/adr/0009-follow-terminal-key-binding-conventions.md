# キーバインドを端末ツールの慣行に揃える

## Context and Problem Statement

端末上で内容を送り読みする道具は既に多く、利用者は本ツールだけを使うわけではない。
pager、editor、他の棋譜ツールを同じ端末で行き来する。

移動と再生の操作が慣行から外れると、他の道具から持ち込んだ手癖がそのまま誤操作になる。
特に手を進める操作は最も頻度が高く、取り違えると意図しない局面へ飛ぶ。

一方で、悪手だけを辿るという本ツール固有の操作には、対応する慣行が存在しない。

## Decision Drivers

* 他の端末ツールと行き来したときの誤操作を避けたい。
* 固有の操作を、既存の慣行と衝突しない形で足したい。

## Considered Options

* 端末ツールで広く使われている慣行に揃え、固有の操作だけを空きキーに足す。
* 特定の既存ツールの操作体系をそのまま踏襲する。
* 用途に最適な操作体系を独自に定義する。

## Decision Outcome

端末ツールで広く使われている慣行に揃え、固有の操作だけを空きキーに足す。

移動は矢印キーと vim の `hjkl` の双方を受け付ける。
先頭と末尾への移動は pager の `g` と `G`、自動再生の開始と停止は `Space`、ヘルプは `?`、終了は `q` に割り当てる。

特定のツールを基準にする案は採らない。
基準にしたツールの操作が変わるたびに追随の判断が生じ、さらに用途の異なるツールの都合まで引き受けることになる。
慣行そのものを基準にすれば、追随先は変化しない。

独自に定義する案も採らない。
本ツールの利用時間は併用する道具より短く、覚え直しの負担が最適化の利点を上回る。

悪手だけを辿る移動は `j` と `k` に割り当てる。
vim における上下移動と意味が近く、手順リスト上を項目単位で移動する操作として矛盾しない。

### Confirmation

移動と再生の操作が、矢印キーと `hjkl` の双方で同じ結果になることを確認する。
固有の操作が、慣行として別の意味を持つキーを奪っていないことを確認する。

## Consequences

### Good

* 他の端末ツールから持ち込んだ手癖がそのまま通る。
* 固有の操作が少数に絞られ、覚える対象が明確になる。
* 追随すべき対象が特定の実装ではないため、外部の変更で判断を迫られない。

### Bad

* 本ツールにとって最適とは限らない配置を受け入れることになる。
  操作の習得コストのほうが大きいと判断して引き受ける。
* 慣行そのものに揺れがあり、`g` と `G` のように解釈が分かれるキーが残る。
  分かれる場合は pager の解釈を優先し、ヘルプで実際の割り当てを示す。
