# v1 は主手順のみを対象とする

## Context and Problem Statement

本格的な解析ツールの中核は、変化手順を枝として持つ木構造にある。
枝を刺し、昇格させ、保存する機能まで含めるかどうかで、v1 の規模が決まる。

## Decision Drivers

* 最初に動くものを出すまでの期間を短くしたい。
* 主な用途である「自分の悪手を確認する」に必要な機能を優先したい。

## Considered Options

* 主手順のみを扱う線形のモデルで実装する。
* 最初から変化手順の木構造を実装する。

## Decision Outcome

主手順のみを扱う線形のモデルで実装する。

局面の列を配列として保持し、手番号で位置を示す。
読み込み時に変化手順が現れた場合は読み飛ばす。

木構造を最初から入れると、読み取りと書き出しの双方を汎用に実装する必要が生じ、v1 の規模が数倍になる。
一方、指した手を順に辿って評価値の変化を見る用途は、線形のモデルで満たせる。

### Confirmation

変化手順を含む PGN を読み込んだとき、主手順が正しく再生され、処理が失敗しないことをテストで確認する。

## Consequences

### Good

* データ構造が配列で済み、位置の管理が単純になる。
* 読み込みと書き出しの双方が小さく保たれる。

### Bad

* 読み込んだ変化手順が失われる。
  書き出し時に元のファイルを上書きしない運用にして、入力側の情報は保全する。
* 解析結果を見て別の手を試す、という使い方ができない。
  必要になった時点で ADR を追加し、モデルの変更として扱う。
